# 성능 기록

측정: `unity/Assets/CatIsland/Tests/PlayMode/ReleaseChecks.cs` `Perf_FiveCatsAndItems` (고양이 5마리 + 용품, 6초 평균). 결과는 `unity/Builds/perf.txt`.
에디터(맥) 수치라 프레임 시간은 참고용이다. 그리기 횟수·삼각형 수는 기기와 같다. 아이폰 실기 값(프레임·메모리)은 `RELEASE_TODO.md` 7번 실기 테스트 때 Xcode 계기판으로 채운다.

## 실기 (iPhone 17 Pro, A19 Pro, 2026-10-10 개발용 Release 빌드)
- 처음 화면(고양이 만들기 + 미리보기 고양이): 켜고 몇 초 로딩 동안 끊김(최대 2.3 s, 0.3 s), 그 뒤 **60 fps** 유지. 10초마다 잰 값에서 가끔 한 번 튐(최대 64~115 ms, 25 ms 넘는 프레임 0~3개).
- 오류·예외 0 (기기 콘솔 60초). 기록: `PerfMonitor` 로그 `[CatIsland] perf`.
- **GC 폭주 찾아 고침 (같은 날)**: 성능 기록에 GC·메모리를 넣어 보니 첫 화면에서 5초에 GC 35~47번, 튄 프레임(65~83 ms)이 모두 GC 와 겹치고 메모리가 93→232 MB 로 늘었다. 범인: 출시 빌드에 남은 개발용 정보 표시(DebugOverlay)의 OnGUI(꺼져 있어도 매 프레임 IMGUI). 개발 빌드에서만 붙이자:

| 실기 iPhone 17 Pro | fps | 가장 긴 프레임 | GC / 5초 | 새 메모리 | 전체 메모리 |
|---|---|---|---|---|---|
| 첫 화면 (고치기 전) | 56~58 | 65~83 ms | 35~47 | - | 93→232 MB 증가 |
| 첫 화면 (고친 뒤) | 60 | 17 ms | 0 | 0.2 KB/프레임 | 85 MB 그대로 |
| 시연 섬 (고양이 3·용품 3) | 60 | 18~19 ms | 0~1 | 0.2~0.7 KB/프레임 | 101 MB 그대로 |

- 기기에서 재는 법: `[CatIsland] perf` 로그(devicectl --console), 부품 끄기 `CATISLAND_DISABLE=종류,종류`.
- 남음: 고양이 5마리, 아이폰 SE 같은 낮은 기기.

| 날짜 | 고양이 | 평균 ms | 최악 ms | 그리기 횟수 | 삼각형 | 비고 |
|---|---|---|---|---|---|---|
| 2026-10-06 | 5 | 16.7 (60fps 고정) | 30.6 | 120 | 209k | 예전 에셋. 메모리 수치는 에디터 전체라 기록 안 함 |

기준: 그리기 횟수 400 미만(테스트가 막음), 삼각형 30만 미만, 아이폰 SE(2세대)에서 60fps.
얼굴의 눈·수염 조각은 고른 것만 원래 재질에 합쳐 그리므로(CatFace) 고양이 한 마리 그리기 횟수는 그대로다.
